# Clean-room review

Check a change against the two rules in `.agent/context/04-legal.md`. This is a gate, not a style
review: the question is only whether the project can ship the change.

## 1. Establish provenance

For every added or modified file, answer *where did this come from*:

- Written by the contributor from public sources → proceed.
- Generated by a tool from public sources → proceed, note the tool in the pull request.
- Copied from anywhere else → find out from where, exactly, before going further.

Provenance that cannot be stated is a blocker. "I don't remember" means no.

## 2. Asset check (rule 1)

| Look at | Blocker |
| --- | --- |
| Images, audio, models, fonts, UI textures | extracted from, or drawn to imitate, Gwent or *The Witcher* |
| Card names, character names, faction names, ability names | taken from or evoking official material, including transliterations and near-misses |
| Flavour text, descriptions, lore strings | taken from or written to imitate official text |
| Card data files (stats, lists, ids) | extracted from an official client, even if retyped by hand |

Generic rules vocabulary — row, round, pass, mulligan, draw, deck, hand, points — is fine.

Signals worth a second look: suspiciously complete card lists; internal-looking ids
(`nilfgaard_soldier_03`); art with no source file, no layers and no author; filenames or metadata
carrying an official product name; EXIF or asset metadata pointing at a game install directory.

## 3. Implementation check (rule 2)

Blockers: decompiled or disassembled code in any amount; dumped data; internal constants or
identifiers lifted from official binaries; code written while reading any of the above.

Accepted: implementations from public wikis, patch notes, rules explanations, videos, and the
contributor's own play experience.

The line is: **mechanics are not copyrightable, specific expression is.** Reimplementing what a
mechanic does is fine. Reproducing how someone else wrote it is not.

Ask for the public source behind a rules change and check it is recorded in the commit body.

## 4. Licence check

- Code contributions land under MIT; original assets under CC BY 4.0, unless the pull request marks
  an asset otherwise.
- New third-party dependencies need an MIT-compatible licence, named in the pull request.
- The contributor must actually have the right to grant these.

## 5. Report

State a verdict per finding, most severe first:

- **Blocker** — quote the file and what rule it breaks. The change cannot be merged as-is.
- **Needs provenance** — the material might be fine; the origin has to be stated first.
- **Clear** — nothing found.

Give the contributor the accepted route alongside the rejection: what public source they could
reimplement from, or what original asset would replace the one being rejected.

When you are unsure, say so and escalate to a maintainer. Do not approve on "probably fine" — the
cost of a false positive here is a takedown, not a bug.
